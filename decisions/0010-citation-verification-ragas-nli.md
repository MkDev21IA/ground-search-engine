# 0010 — Citation Verification: RAGAS First, NLI On-Demand

**Status:** Accepted (prototype direction)
**Date:** 2026-09-03

## Context

[0009](0009-source-content-extraction.md) solved the mechanics of extracting clean text from source URLs, but left open the mechanism required to verify whether a given claim generated by the LLM is actually entailed by that extracted text.

The **RAGAS** framework was evaluated to determine whether an LLM-as-judge setup suffices, or whether an explicit Natural Language Inference (NLI) model (e.g., DeBERTa) is required.

## RAGAS: Core Metrics

| Metric | What it measures | Project Role |
|---|---|---|
| Context Precision | Is retrieved context relevant and signal-rich? | Evaluates the search proxy's retrieval quality ([0006](0006-search-evaluation-methodology.md)) |
| Context Recall | Does retrieved context contain complete information? | Measures retrieval coverage gaps |
| Faithfulness | Is the synthesized answer fully grounded in the retrieved context? | Core verification problem (claim-level grounding) |
| Answer Relevancy | Does the response directly address the user prompt? | Checks against conversational drift or evasive refusals |

## LLM-as-Judge vs. NLI

Literature benchmarks demonstrate that LLM-as-judge approaches (decomposing answers into atomic statements and checking entailment against context) correlate more strongly with human ground truth than generic off-the-shelf NLI models. Specialized lightweight models (e.g., MiniCheck, HHEM, Vectara) offer high efficiency, but adding them prematurely increases pipeline complexity.

## Decision

1. **Prototype first with RAGAS (LLM-as-judge)**: Configured via standard OpenAI-compatible endpoints to use local models or fast reference models.
2. **NLI or lightweight hallucination detection models only on-demand**: Introduce smaller specialized models (e.g., MiniCheck) as a pre-filter only if the token cost or latency of LLM-as-judge evaluation becomes a measured bottleneck.
3. Complementary with [0008](0008-future-evaluation-with-promptfoo.md): Promptfoo covers CLI regression and red-teaming, while RAGAS specifically measures RAG groundedness.

## Consequences

- Follows the core engineering principle: measure before adding extra model pipelines.
- Implementation of automated evaluation suite is deferred until after core response pipeline integration.
