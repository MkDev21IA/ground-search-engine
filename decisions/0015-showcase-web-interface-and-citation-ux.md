# 0015 — Showcase Web Interface Architecture and Verified Citation UX

**Status:** Accepted  
**Date:** 2026-09-25  

## Context

Following the completion of the backend service and streaming Server-Sent Events (SSE) endpoints ([0014](0014-backend-service-architecture-and-telemetry.md)), the final milestone of the sprint ([0012](0012-head-to-head-evaluation-and-cost-benchmark.md)) is to provide a user-facing interactive web application.

The web interface must satisfy several operational and UX objectives:
1. **Interactive Verification & Auditability**: Every factual assertion generated by the engine should visibly map to its underlying primary or secondary web sources. Users should be able to inspect source cards, read extracted snippets, and click inline citation badges to verify provenance.
2. **Real-time Pipeline Transparency**: Rather than displaying an opaque loading spinner for 10–15 seconds, the UI must visualize the live streaming pipeline lifecycle: `Search` -> `Extract` -> `Synthesize`, rendering source cards as soon as extraction finishes and streaming tokens as they are generated by the model.
3. **Telemetry & Cost Transparency**: Expose per-stage latency breakdowns (search ms, extract ms, synthesis ms, total ms), token usage (`prompt_tokens`, `completion_tokens`), and exact USD cost calculations per query.
4. **Bring Your Own Key (BYOK) & Privacy Sovereignty**: Empower users to switch models (e.g., Llama 3.2 3B, Qwen 2.5 7B, GPT-4o-mini, Gemini 2.5 Flash), configure custom OpenAI-compatible base URLs (such as local Ollama / vLLM at `http://localhost:11434/v1`), and supply their own API keys via client-side `localStorage`, sending them in request headers without server credential lock-in.
5. **Zero-Build Dependency Architecture**: Avoid bloated Node.js / npm toolchains (`webpack`, `vite`, `node_modules`). The entire web interface should be bundled and served directly by FastAPI (`StaticFiles`), allowing anyone cloning the open-source repository to start the complete full-stack engine simply with `python -m search_proxy.cli serve`.

## Decision

### 1. Technology Stack

Adopt a lightweight, modern, zero-compilation frontend stack:
- **Semantic HTML5 & Modern CSS**: Clean structure with modern responsive layout.
- **Tailwind CSS (Play CDN)**: Utility-first CSS framework loaded via CDN (`tailwindcss.com`), delivering a dark-mode palette (slate, zinc, emerald accents) without requiring an npm build process.
- **Vanilla ES6+ JavaScript**: Native browser standard using `EventSource` / `ReadableStream` fetch API for real-time SSE streaming, DOM manipulation, and `localStorage` credential persistence.
- **Marked.js**: Fast, client-side Markdown parser loaded via CDN to render synthesis answers, lists, and formatting on the fly while streaming tokens.

### 2. File Organization and Service Integration

The web interface assets will be located directly in the Python package under `search-proxy/search_proxy/ui/`:
- `index.html`: Main single-page interface layout (header, status indicators, search bar, example prompts, pipeline visualizer, source cards grid, streaming answer container, and telemetry panel).
- `app.js`: Reactive controller managing search submission, SSE lifecycle events (`status`, `search_results`, `extraction_complete`, `token`, `citations`, `telemetry`, `done`), BYOK credential management, and Markdown citation enhancement.
- `styles.css`: Custom animations, citation pill styling, scrollbar theming, and responsive adjustments.

In `search_proxy/api/app.py`, the static directory is mounted at `/`, serving `index.html` as the default document while preserving `/docs` and `/redoc` for interactive OpenAPI documentation, and `/api/*` for REST endpoints.

### 3. User Experience & Citation Interaction Model

- **Source Cards Section**: Positioned prominently above or alongside the answer. Each source displays:
  - Favicon / clean domain badge (e.g., `nasa.gov`, `nature.com`).
  - Title with direct external link.
  - Extraction tier pill: `Full Text` (emerald) vs `Snippet` (amber) vs `Blocked` (zinc).
  - Clean word count and text snippet preview.
- **Interactive Inline Citations**:
  - The LLM outputs citations in standard Markdown `[Source Title](URL)` format.
  - The client parser transforms these links into branded interactive citation badges (e.g., `[1: NASA JWST]`).
  - Hovering over an inline citation highlights the corresponding source card in the sources grid.
- **BYOK Configuration Drawer**:
  - Accessible via a gear icon in the header.
  - Allows overriding Model, Base URL, and API Key.
  - Pre-fills recommended models fetched dynamically from `/api/models`.
  - Persisted in browser `localStorage`.

## Consequences

- **Instant Full-Stack Distribution**: Anyone can run the complete search and factual synthesis engine with a single Python command without needing Node.js or frontend bundlers.
- **Visual Validation of ADR Goals**: The interface provides an immediate visual proof of the project's core mission: factual answers backed by verifiable primary sources, transparent costs, and zero vendor lock-in.
- **Extensible Base**: Serves as a modular foundation for future enhancements (e.g., multi-turn conversational follow-ups, PDF export, or multi-engine selection).
